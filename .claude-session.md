## Architecture (payments)
- `POST /api/resident/sessions/:id/pay` creates or reuses a PaymentIntent; price comes from `sessions.price`. A `pending` transaction row stores `pi_...` in `provider_ref`.
- `POST /api/payments/webhook` uses a raw body and verifies the signature. `handleStripeEvent` inserts the event id into `stripe_events` (dedupe) and runs the handler inside one DB transaction.
- `onPaymentSucceeded` confirms the session; `onPaymentFailed` records the decline reason; `onPaymentCanceled` marks `failed`.
- Session hold is 10 minutes. Transaction status enum: `pending`, `succeeded`, `failed`, `refunded`.
